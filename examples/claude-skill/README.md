# Claude Code 스킬 틀 붙이기

[Claude Code](https://docs.claude.com/en/docs/claude-code)가 perfkit을 같은 순서(금지 → 관문 → 세 흐름)로 돌리게 하는 스킬 틀입니다. perfkit 없이 쓰는 것이 아니라, perfkit 명령을 언제·어떤 순서로·무엇을 하지 않고 부를지 정해 두는 지침입니다.

## 붙이는 법

1. 게임 프로젝트에 폴더를 만들고 틀을 복사합니다.

   ```
   mkdir -p <게임 프로젝트>/.claude/skills/perf-check
   cp examples/claude-skill/SKILL.md <게임 프로젝트>/.claude/skills/perf-check/SKILL.md
   ```

   팀이 함께 쓰려면 게임 저장소에 커밋하고, 개인용이면 `~/.claude/skills/perf-check/`에 둡니다.

2. `<…>` 자리를 채웁니다.

   | 자리 | 예 |
   |---|---|
   | `<게임 이름>` | 스킬 설명에 보이는 이름 |
   | `<perfkit 클론>` | `~/tools/unity-perfkit` |
   | `<프로필 경로>`, `<결과 폴더>` | 사용자 설정 `profile`·`paths.results`와 같은 값 |
   | `<측정 모드 코드 경로>`, `<에디터 측정 도구 경로>` | 측정 모드를 넣은 C# 폴더 |
   | `<측정 브랜치>`, `<실험 브랜치 접두어>` | `perf/probe`, `perf/exp-` |
   | `<빌드 명령>`과 G6 인자 | 프로필 `[build] command`와 같은 도구 |
   | `<에뮬레이터 이름>`, `<시나리오>` | 프로필 `[devices.<이름>]`, `[[scenarios]] name` |
   | `<안전 범위 목록>` | 사람 승인 없이 고쳐도 되는 항목 ID와 조건 |
   | `<에디터를 여는 절차>` | 에디터를 여는 사람·도구, 닫기 전에 커밋하는 규칙 |

3. 프로젝트에 맞지 않는 절은 지웁니다(예: 에디터 측정 도구가 없으면 2절 3번과 L2 언급, 실기기가 없으면 G5).

4. 길게 늘어나는 내용(명령 모음, 지표별 등급 표, 가설 카드 서식, 안전 범위 세부)은 `references/`에 나눠 두고 SKILL.md에는 「필요하면 Read」 줄만 남기면, 긴 세션에서 컨텍스트가 줄어도 0절이 남습니다.

## 지키면 좋은 것

- **0절(금지·관문)을 파일 앞쪽에 둡니다.** 등급 혼용 금지, 1회 측정 판정 금지, 「판단 보류」를 개선으로 쓰지 않기는 프로젝트가 달라도 그대로 둡니다.
- **명령은 `--help`로 확인한 것만** 적습니다. perfkit 판이 바뀌면 `python -m perfkit <명령> --help`로 다시 봅니다.
- **수치는 적지 않습니다.** 잡음 등급·판정 제외·문턱은 프로필이 정본이고, 스킬에는 「프로필 `<절>`을 본다」만 씁니다. 수치를 스킬에 복사하면 프로필과 어긋납니다.
- 다른 에이전트(Cursor 등)용으로 바꿔 쓸 때도 0절의 순서와 문장은 그대로 두는 편이 안전합니다.
